# 图片视觉导演：纯图片模式

## 输入与边界

读取文案、SRT，以及可选的配音、参考风格图、画幅、受众、目标片段、图片预算、已有素材清单/检索结果。沿用当前项目 BRIEF 和对话里已确认的选择，不重新询问。

- 本模式设计图片内容、匹配候选素材、提供生图/编辑提示词和展示时间；不调用生图接口，不制作视频，不把素材写入公共库。
- 公共素材库独立于视频项目。`media-assets` 负责检索、身份/来源与使用许可、正式选用、入库及版本记录；导演说明素材需求，判断可见图片是否符合画面意图，并引用它返回的真实素材 ID。
- 缺图提示词属于制作交接，无需配置 API。后续生图工具和 Remotion/HyperFrames 可以更换。
- 没有提供素材库、没有权限访问、实际搜索但无合适结果，是三种不同状态。不能把“没查”写成“库里没有”。

## 1. 理解原文，确定视觉语言

用户选择导演方案、画风预设或提供 `DIRECTOR.yaml` 时，先按 [配置选择与覆盖规则](director-presets.md) 读取并合并。导演方案决定内容表达，画风可单独替换；将有效规则保存到本项目 direction/style，不把配置名直接当作生图提示词。

先识别文案的主线、重要转折、对比、具体事物和抽象关系。给每个画面一个明确的理解目标，避免把所有句子都配成泛化的风景、人物或装饰图。

确定全片比例、媒介、配色、人物连续性、信息密度和字幕安全区。画风与受众来自用户/BRIEF，不把某个频道、健康题材、中老年观众或某种模型画风写成通用默认。

先按 [交付前审查](image-plan-review.md) 确定连续主角、多角色或无人物。将必要的稳定人物/环境设定写进全局 style，再展开逐镜提示词；受众年龄不等于角色身份。

实际查看参考图后才描述其风格；参考视觉语言，不照搬内容。没给风格时可提出一个临时方向并标明假设，不虚称用户已确认。既有风格明确时直接沿用。

生活内容可用人物行为和物件关系；对比可用并列、前后变化；抽象关系可用隐喻。说明图为示意，不把生成图伪装成真实报道、研报截图或实验证据。准确图表/表格交给确定性绘图/排版，记录 `external_design` 需求和真实数据来源。遵循 evidence-rules，不把相关性画成因果，不增强原稿的医学疗效或投资结论。

## 2. 按语义拆分，映射真实时间

使用 `python3 scripts/image_timeline.py parse INPUT.srt` 解析字幕。脚本只处理机械时间与文本，不替代导演决策。

- 图片数量随语义、停顿、阅读负担和预算决定；一张图可以覆盖多条字幕。不要机械每条字幕一图、每几秒一图，也不要为了凑满十张而拆碎完整意思。
- 切图优先安排在话题、对象、因果、对比或情绪变化处。静音期间明确延续上一图、切下一图或安排留白画面，保留原始时间，不压掉停顿。
- 按毫秒整数记录 `[startMs,endMs)`；视觉区间连续覆盖用户请求的片段。部分视频保留原始绝对时间，不擅自从零重写 SRT。
- 同一字幕内的语义转折可以拆镜；只有听取音频或用对齐结果核验后才标 `audio_verified`，否则标 `estimated` 并列入待核验项。毫秒字段不代表真实词级精度。
- 只有 SRT 时不能声称音画同步已经验证，字幕尾点也不能冒充音频总时长。
- SRT 与原稿不一致时记录重要差异，按实际口播/字幕安排，不自行改写内容。SRT 格式有误时报告具体条目，不猜时间。
- 只有文案时照常输出无时间草案：`timing.kind=untimed`，所有时间 null，字幕引用为空；状态 planned。收到 SRT 后映射原分镜。

## 3. 写素材需求并选择路径

先写每镜 `assetNeed`（主体、行为/关系、风格、构图、画幅、清晰度），再查看 `media-assets` 提供的候选或用户给出的素材。

| action | 含义 | 交付 |
|---|---|---|
| reuse | 已查看、符合意图，素材使用状态已有确认 | 真实 assetRef；prompt 为 null；裁切/运动在 usage 内 |
| edit | 已查看、可用于编辑的素材需要变更内容 | 原素材引用＋明确编辑提示词；制作器将结果作为新素材/版本 |
| generate | 确需新图片，或未提供素材库而规划新图 | 完整生图提示词；assetRef 为 null，不能预造入库 ID |
| search_pending | 有候选但无法查看、检索未完成或使用状态未确认 | 候选 ID/搜索条件＋具体待办；可附备用提示词 |
| external_design | 精确图表/排版等不宜让生图模型绘制 | 真实数据、来源、标签和布局要求；prompt 为 null |

只看文件名或文字描述，不能把素材标成已查看。视觉适配与来源许可分开：导演不根据“看起来合适”自行批准使用。不要重新遍历公共库来替代 `media-assets`，也不建立第二份素材库。

同图允许跨项目复用。图片原文件和身份属于素材库；本项目的裁切、运动、叠字及出现时间属于 usage。不覆盖公共原图，新图 ID 和版本由后续素材环节分配。

## 4. 提示词与文字分层

每条生图提示词自包含：主体、动作、环境、构图/关系、完整风格描述、比例与留白、准确的图中文字要求及针对性的排除项。不能只写“同上”“保持前图风格”。连续人物重复稳定特征，并引用真实可用参考。

描述一张图能呈现的明确瞬间；时间变化与后期运动分开。只在有实际备用需求时写 fallbackPrompt，并保留同镜表达目标、角色及画风约束。提示词堆积排除项不能代替具体、合理的构图。

一条素材需求对应一张独立图片。允许单张图片内有意义的对比构图，禁止把多个分镜合成九宫格、联系表或多图拼版作为最终素材。

- `narrativeBeat`：内部表达目标，不直接上屏。
- `image.inImageText`：实际要画进图片的逐字文字，默认 []。
- `image.overlay`：后期叠加的标题、关键词、标签，和逐句口播字幕分开。

默认将需要准确、可修改的文字留给后期。用户明确要求图文图片时遵从，列出准确文案并安排后续字形检查。提示词不能夹带“开场钩子”“痛点放大”等内部策划标签。文字为空就明确原图无字；不能一面要求无字、一面让模型画标题。

## 5. 交付、检查、继续

按 image-storyboard-contract 写入同一个 `STORYBOARD.md`：全局视觉规范、逐镜可读表和一份规范 JSON 区块。完整提示词在该 JSON 中；用户要单独复制时可以另行展示，但保持逐字一致。不另建一套可独立编辑的视觉计划。

修订以完整镜头为单位，执行 [跨字段修订与复查](image-plan-review.md)：实际读取已保存的 JSON，对齐画面意图、素材需求、主/备用提示词、上屏文字、编排及可读表；修复后重新读取问题字段，再生成审查结论。不能只更换提示词或新增“已检查”说明而保留已知矛盾。

运行 `python3 scripts/image_timeline.py validate STORYBOARD.md --srt INPUT.srt`，无时间方案不传 SRT。用户/项目选择了预设时，按 [配置校验约定](director-presets.md) 传入原始选择的 ID，不能只运行不检查预设的兼容命令。修复结构、时间与配置声明错误，再按 [交付前审查](image-plan-review.md) 对实际屏幕文字、主/备用提示词和编排进行语义审查并修订。脚本的 checks/notChecked 表示检查范围，不验证审美、事实、提示词是否忠实执行了配置或听觉同步。

交付时分别说明：导演方案完成程度、素材是否已选定/待制作、时间哪些未核验。`status=ready` 只表示方案可交接，不表示已生图、入库或成片。有临时风格、估计切点、待查素材或关键差异时保持 planned 并列出 openQuestions。

用户只要求设计时到此结束。需要进入制作时，把素材请求交给可用制作工具/素材能力；收到素材 ID 后更新原分镜。只有进入执行阶段才确定每镜 renderer，并交给已有引擎 Skill；不擅自自动推进。
